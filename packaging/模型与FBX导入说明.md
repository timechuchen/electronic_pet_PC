# 模型与 FBX 动作导入

本次功能位于带 AI 聊天的独立桌宠开发版 `packaging/`。双击项目根目录的 `启动AI桌宠.command`，打开桌宠的「设置」，展开右侧「模型与 FBX 动作」。前端已重新构建，可直接启动，不需要再次安装依赖。正在运行的开发版需要退出后重新打开。

`project/` 是较早的 Python / 原生窗口实现；`releases/` 和 `packaging/build/` 是此前的发布产物。1.2.0 已另行生成 macOS / Windows 发布包，位于 `releases/v1.2.0/`；更早的发布包保留。

## 导入角色

1. 点击「导入 VRM」，选择 `.vrm` 文件。
2. 等待模型、内嵌纹理、人形骨架和尺寸校验完成。
3. 在「角色模型」中选择新模型，点击「应用模型」。

支持 VRM 0.x 和 VRM 1.0。应用后桌宠与设置窗口同步切换，重启后继续使用所选角色。模型会按实际尺寸取景，并将脚底放到地面。缺少可选骨骼或表情不会阻止基本播放；眨眼、微笑、说话口型的效果取决于模型自身提供的表情。

「恢复兰洛」切回内置角色。「移除模型」移除列表中选中的自定义模型；移除正在使用的模型时自动恢复兰洛。导入不覆盖原始模型文件。新模型加载失败时保留当前能显示的角色，可重新应用或恢复兰洛。

## 导入动作

1. 点击「导入 FBX 动作」，选择 `.fbx` 文件。
2. 从列表选择动画片段。空片段及超出 0.1–3600 秒范围的片段不可选。
3. 检查「骨骼映射」。程序识别 Mixamo、VRM 标准名称和部分 Blender / Unreal 常见命名；无法识别的源骨骼可手动对应到标准人形骨骼。每根源骨骼只能使用一次，不需要的骨骼可以不映射。
4. 默认勾选「原地播放」，保留上下运动，去掉水平位移。若要保留行走轨迹，可取消勾选，长距离动作可能移出视野。
5. 点击「保存 FBX 动作」，再点击库中的动作播放。

支持暂停、0.25×–2× 速度、循环、复位及表情叠加。摄像头跟随仍优先于手动动作。切换角色后会对当前角色重新转换 FBX 骨骼轨道。一个文件有多个片段时，可再次导入并选择另一个片段分别保存。自定义 FBX 当前用于手动播放和循环；现有待机／音乐预设仍使用原先的内置动作列表。

## 格式与兼容范围

- 单文件最大 128 MB；最多 16 个自定义模型和 64 个 FBX 动作片段，另有原来的 JSON 动作库。
- VRM 必须是包含人形描述的有效 GLB，纹理及缓冲区须内嵌。外部链接资源会被拒绝。
- FBX 必须有能映射到人形骨骼的旋转动画。只有网格、摄像机动画、未烘焙约束、非人形骨架，不能保证用于 VRM。
- 推荐导出 FBX 7.x、烘焙骨骼动画及 T 姿态骨架。源骨架比例、静止姿态、轴向及约束不同，仍可能需要在建模软件中修正。手动映射解决名称对应，不会自动修复所有骨架差异。
- 不会把 FBX 材质或网格作为角色导入，也不会请求其外部纹理。它仅用于骨骼动作；表情／形态键动画不在本次转换范围内。
- 已测试当前兰洛 VRM 0.x、项目自建的最小 VRM 1.0 测试人形、现有街舞 FBX，以及重命名为非标准骨骼的 FBX。没有声称已经覆盖所有第三方导出器。

加载器的格式范围参考 [Three.js FBXLoader 官方文档](https://threejs.org/docs/pages/FBXLoader.html)。旋转重定向基于 [three-vrm 官方 Mixamo 示例](https://github.com/pixiv/three-vrm/blob/dev/packages/three-vrm/examples/humanoidAnimation/loadMixamoAnimation.js)，增加了片段选择、手动映射、相对骨架高度与导出原点处理。

## 项目分析与实现

原项目采用 **Electron 窗口 + Python 状态服务 + Three.js / three-vrm 渲染**：Python 管理动作时间线，通过 SSE 同步窗口；前端按时间直接采样骨骼。原先模型路径与街舞路径固定，FBX 只读第一个片段、只认 Mixamo 名称。因此只添加文件选择按钮不足以支持任意用户素材，还需要保存、切换、映射和重新绑定。

本次沿用原架构：

| 文件 | 作用 |
| --- | --- |
| `backend/pet/assets.py` | 模型及动作清单、文件类型与大小校验、随机内部文件名、原子保存、删除与默认模型选择 |
| `backend/app.py` | `/api/library`、二进制上传接口、仅对已登记素材开放的读取路径、SSE 素材版本通知 |
| `backend/pet/controller.py` | 为 FBX 注册独立动作 ID 和时长，复用现有暂停、循环、速度和表情通道 |
| `backend/web/src/asset-library.js` | 本机文件校验、导入进度、片段选择、骨骼对应、模型及动作管理 |
| `backend/web/src/retarget.js` | 可重用 FBX 解析／转换、名称识别、手动映射、髋骨缩放、原地播放 |
| `backend/web/src/main.js` | 保留旧角色直到新模型可用，释放旧 GPU 资源，重新绑定动作，两窗口同步 |

素材保存到应用用户数据目录的 `assets/`：原始 `.vrm` / `.fbx` 和 `library.json`。文件路径使用程序生成的 ID，不使用上传文件名拼接磁盘路径。清单原子替换，写入失败不会改变当前库；接口继续使用本机令牌。摄像头、AI 聊天和 JSON 动作库保留原有机制。

## 验证

在项目根目录运行：

```sh
python3 -m unittest discover -s packaging/tests -p 'test_*.py'
node packaging/tests/retarget.mjs
node packaging/tests/verify-assets.cjs
node packaging/tests/verify-actions.cjs
node --test packaging/tests/chat-service.test.cjs
```

Electron 测试使用独立临时用户目录，不修改日常桌宠配置。导入测试覆盖 VRM 0/1 切换、FBX 动作与非标准骨骼映射、两窗口同步、暂停、损坏文件拒绝、移动端布局、重启恢复及播放中删除。结果与截图位于 `test-data/assets-dev/`。
